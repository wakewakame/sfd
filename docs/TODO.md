## find.json のビュアー

似ていると判定されたファイルを見比べて、どれを残すか決めるためのもの。
ブラウザで動かし、**残すもの・消すものをまとめた JSON を書き出すところまで**を
担当する。実際に消すのはビュアーの仕事にしない。

エクスプローラーでファイルを選択した状態で開く案は見送った。ブラウザからは
できないため。`http://` のページから `file://` を開くのはどのブラウザも塞いで
いるし、仮に開けても「開く」であって「ファイラで選択する」ではない。やるなら
ローカルサーバを立てて `explorer.exe /select,...` を叩かせることになるが、
localhost で待ち受けるサーバは他のどのページからも叩けるため、トークンや
Origin の検証が要る。そこまでするほどの機能ではないと判断した。

作るときに決めること:

- **画像をどう読み込むか。** ページ自体を `file://` で開けば `<img>` は隣の
  ファイルを読めるが、`fetch` は塞がれるので find.json の読み込み方を考える必要が
  ある。ファイルを選択させて `FileReader` で読むのが素直かもしれない
- **書き出す JSON の形。** 消す側を列挙するのか、残す側を列挙するのか。
  消す側だけだと「まだ判断していない」と「消さないと決めた」が区別できない
- **書き出した後に誰が消すか。** `sfd` のサブコマンドにするか、シェルスクリプトを
  出すか。前者なら誤削除を防ぐ確認の作り込みが要る

## 分かっているが直していないこと

### find.json の `identical` がグループ先頭としか比較していない

`similar` に並ぶファイル同士がバイト単位で同一でも、先頭と違えば印が付かない。
「この 2 つは中身が同じなので見ずに片方消してよい」が読み取れない。

直すなら、グループ内で sha256 が一致する組にも印を付けるか、出力に sha256 の
先頭数桁を含める。どちらも小さいが、出力形式が変わる。

### `sfd find` が 20 万件を超えると数分かかる

実測で 5 万件 18 秒、きれいな二乗スケール (dihedral 込み、1 スレッド)。
貪欲法の外側ループは逐次だが、**各先頭に対する走査は並列化できる**。意味は
変わらないので、30 行程度で 8 倍になる。手持ちのコレクションの規模次第。

### 読めるようになったディレクトリの古いエラー行が残る

権限がなくて読めなかったディレクトリは `error` 行として記録されるが、権限を
直しても打ち消す行が書かれない。配下のファイルは埋まるのに、そのディレクトリの
行は「読めない」と言い続ける。

`find` は `error` 行を読み飛ばすので動作に影響はなく、`--no-resume` で消える。
直すなら、探索中に読めたディレクトリを覚えておいて、以前エラーだったものに
`error` も `pdq` も持たない行を書いて打ち消す。
